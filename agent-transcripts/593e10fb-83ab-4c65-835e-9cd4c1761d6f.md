- Every module docstring cites the doc section it implements and names the phase where the rest lands, so the skeleton reads as a deliberate contract rather than stubs.

## 2. What the product is meant to be (PRD)

A grounded RAG assistant over 303 Lenny's Podcast transcripts, framed as a **forward-deployment engagement** — the evaluator must be able to clone, run, trust, and extend it. The governing principle (§25): *"grounded usefulness over generic intelligence."* Priority order is explicit: source grounding → retrieval quality → provenance → reliable generation → UX → operational simplicity.

**Success metrics (§3)** — these are measured, not vibes:
- Grounded Answer Rate ≥ 90% (answer + ≥1 relevant source)
- Retrieval relevance ≥ 80% on a **manually created eval set**
- Unsupported-question behaviour ≥ 90% (says it can't, rather than inventing)
- Evaluator can start the app from the README alone

**Five capability pillars**: conversational assistant with sessions/follow-ups/attribution; knowledge base with ingestion + incremental refresh + provenance; agent with RAG, Ship 30 essay skill, Markdown + HTML/CSS artifact skills; configurable Ollama/cloud providers with availability surfaced in the UI; split chat/artifact viewer with sanitised HTML.

**Explicitly out of scope (§5.2)**: real-time ingestion, user-uploaded KBs, multi-tenancy, fine-tuning, web research beyond the corpus, analytics dashboards, mobile, and **arbitrary JS execution inside artifacts**.

**Ship 30 skill (§11)**: ~1,250 words, strong hook, narrative progression, headings, bullets, selective bold, one specific actionable takeaway, all claims grounded, returned as a Markdown artifact, generated *through a dedicated skill* (not just a prompt).

**Artifact security (§14, §22.6)**: generated HTML is untrusted — sanitise, isolate rendering, block parent-app access, restrict browser capabilities, expose no credentials, and **document the boundary** so the evaluator understands what's permitted vs blocked.

**Risk register (§22)** names hallucination, retrieval quality, weak local-model output, latency, cost, unsafe HTML, and data freshness — each with a mitigation that maps onto a concrete implementation choice.

## Part 1 — File-by-file walkthrough

### Backend

**[config.py](backend/app/config.py) (241 lines)** — the only module that touches the environment. Everything else takes a `Settings` object. `.env` now resolves from the `backend/` package rather than the CWD, so `uvicorn app.main:app` works from either directory. Secrets are `SecretStr`, so an accidental log of the settings object prints `**********`. `embedding_dimensions` derives the pgvector column width from the model name and raises on an unmapped model. `app_env` is a behavioural switch, not a label — it drives `local_providers_enabled`, `docs_enabled`, and the production CORS guard.

**[errors.py](backend/app/errors.py)** — 10 typed errors, each with a stable `code`, a user-safe `message`, and an HTTP status. `**context` kwargs go to the log record only and never serialise to the client. This is the contract every failure renders through.

**[logging_config.py](backend/app/logging_config.py)** — structlog; console in dev, JSON elsewhere. `_redact_secrets` scrubs known-sensitive keys before rendering.

**[http.py](backend/app/http.py) (new)** — one pooled `httpx.AsyncClient` for all outbound calls, closed on shutdown. Without it every provider probe paid a fresh TCP+TLS handshake.

**[db/session.py](backend/app/db/session.py)** — async engine for requests, sync engine for the future ingestion CLI. `check_database()` is now bounded by `asyncio.wait_for` and catches broadly: a host that accepts the TCP connection but never replies used to hang `/health` for the driver's full connect timeout.

**[main.py](backend/app/main.py) (219 lines)** — app factory. Middleware order is now deliberate and documented: CORS is registered **last** so it wraps everything, meaning error responses still carry the headers the browser needs to let the frontend read the error body at all. The request-context middleware unbinds contextvars in a `finally` (they previously leaked into the next request on the same worker task), logs `duration_ms`, and drops `/health` to debug level. Added: security headers, `TrustedHostMiddleware` when `ALLOWED_HOSTS` is explicit, and docs disabled in production.

**[api/health.py](backend/app/api/health.py)** — `/health` deliberately does **not** probe model providers. It's polled by orchestrators and must stay fast and deterministic; a missing Ollama daemon makes one model unselectable, not the app unhealthy. That question is answered by `/api/providers`.

### The provider layer (new)

**[models/base.py](backend/app/models/base.py)** — separates two things that must not be conflated:
- `is_enabled` — **policy**: may this provider be used in this environment at all?
- `check_availability()` — **reality**: is it reachable and configured right now?

**[models/ollama.py](backend/app/models/ollama.py)** — probes `/api/tags` *and* confirms the configured model is pulled. A running daemon without `llama3.1:8b` reports unavailable rather than moving the failure to the user's first question. Handles Ollama's implicit `:latest` tag.

**[models/cloud.py](backend/app/models/cloud.py)** — Anthropic. Availability = credential present. No live round-trip: `/api/providers` is called on every page load, and a vendor call there would add latency and cost.

**[models/registry.py](backend/app/models/registry.py)** — the policy engine: TTL-cached probes (15s), safe default resolution, and `require()`.

**[api/providers.py](backend/app/api/providers.py)** — `GET /api/providers`.

### Frontend

## Three judgment calls

1. **Error prose stayed on the exception class.** `ERROR_NOT_FOUND` is in constants because `main.py` and `errors.py` both emit it and the frontend matches on it — it's a contract. The *message* is that class's user-facing copy, and splitting it from the class it describes makes both harder to read. Frontend copy did move to `COPY`, since it's shared across components.

2. **`as const`, not `enum`.** Your tsconfig has `erasableSyntaxOnly: true`, so enums won't compile. `PROVIDER_IDS` is an `as const` tuple with `ProviderId` derived from it — add an id in one place and the type follows.

3. **Shared containers are tuples/frozensets.** `DEFAULT_CORS_ORIGINS` is a tuple copied via `default_factory=lambda: list(...)`, so two `Settings` instances can't alias the same list. There's a test for it.
